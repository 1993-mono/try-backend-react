# 업무일지 기록

에이전트가 「업무일지 어떻게 적을까?」 질문을 받으면 이 파일을 **먼저** 읽고,  
이전 문구 톤·형식에 맞춰 초안을 제안한다.  
채택한 최종 문구는 아래에 추가한다.

---

## 작성 규칙

- **「검토」** 중심. `학습` · `실습` · `예습` 등 표현은 쓰지 않는다.
- 짧고 업무보고용 톤. 한 줄 제목(+ 필요 시 `:` 하위 항목).
- 로드맵 단계와 맞춰 적되, 로드맵 번호·파일명을 그대로 넣지 않아도 된다.
- 프론트/백엔드로 **구분하지 않는다.** 시간 순 한 목록만 유지한다.

### 형식 예시

```
주제 검토: 구체 범위
: 하위 항목 1
: 하위 항목 2
```

또는 한 줄:

```
주제 설정 및 ○○ 연동
```

---

## 이력 (과거 → 현재)

1. JSON 통신 방식 검토: REST API 연동

8. 서버 status 코드·에러 응답 검토
